# واجهات الإدارة — BloodLink

تم تنفيذ الجزء الخاص بالإدارة داخل مشروع React الموجود، بنفس ألوان وخطوط وتفاصيل مرجع `BloodLink_UI_6_Modern_Gov.html`.

**المرجع لا يحتوي على صفحات Admin.** الصفحات الأربع هنا امتداد مقترح لنفس التصميم بناءً على توزيع المهام ومتطلبات المشروع، وتحتاج مراجعتكم من ناحية الشكل النهائي.

## التشغيل

من مجلد المشروع:

```sh
cd client
npm install # أول مرة فقط، أو عند تغيير التبعيات
npm run dev
```

افتح رابط Vite الظاهر في الطرفية وأضف `/admin`؛ المنفذ الافتراضي `http://localhost:5173/admin`.

| المسار | الوظيفة |
| --- | --- |
| `/admin` | ملخص المنصة، قوائم العمل، وسجل الإجراءات المحلية |
| `/admin/papers` | البحث وتصفية الأوراق، معاينة نموذج المستند، القبول أو الرفض مع السبب |
| `/admin/reports` | مراجعة البلاغات، حفظ البلاغ أو تنبيه أو حظر الحساب، وإلغاء الحظر مع السبب |
| `/admin/hospitals` | مراجعة بيانات ومستند الشراكة، اعتماد المستشفى أو رفض الطلب مع السبب |

## تجربة الواجهة

- اضغط على أي مكان في صف المستشفى أو الورقة أو البلاغ لفتح التفاصيل، أو استخدم زر «مراجعة». ينطبق ذلك أيضًا على بطاقات الموبايل وصفوف الحسابات المحظورة. الزر متاح باستخدام Tab ثم Enter أو Space؛ اختيار نص لنسخه لا يفتح السجل.
- نوافذ التفاصيل تبدأ بالتركيز على العنوان، وعند إغلاقها يعود التركيز لزر السجل. مؤشر تركيز الكيبورد بسيط دون الإطار الأصفر الكبير حول المحتوى.
- يجب كتابة سبب من خمسة أحرف على الأقل لتأكيد القرار.
- تُحدّث العدادات وسجل الإجراءات عند اتخاذ القرارات، وتُحفظ في `localStorage` تحت المفتاح `bloodlink-admin-demo-v1`.
- استخدم مرشح «كل الحالات» أو ما يقابله للاطلاع على السجلات المنتهية. تظهر أزرار الترقيم عند تجاوز خمسة سجلات.
- زر «إعادة البيانات التجريبية» متاح أعلى المحتوى على الكمبيوتر والموبايل. يتطلب تأكيدًا قبل استعادة الأمثلة الأصلية.
- الواجهة عربية RTL، وتتحول الجداول إلى بطاقات على الشاشات الصغيرة. يتضمن الهيدر تبديل الوضع الفاتح والداكن فقط، دون أدوات لحجم الخط أو التباين أو رابط «عرض الموقع». الدخول لصفحات الإدارة مباشرة من المسارات الموضحة أعلاه.

## حدود النسخة الحالية

- لا يوجد Backend أو تسجيل دخول أو تحقق من صلاحيات الإدارة؛ الصفحات متاحة مباشرة للتجربة.
- الأسماء والأرقام والأوراق والتراخيص والإحصائيات أمثلة توضيحية؛ لا تُجرى قرارات طبية أو تحقق حقيقي من المستندات.
- المراجعة والحظر والاعتماد والتنبيهات إجراءات محلية؛ لا تُرسل رسائل أو تُنشّط حسابات فعلية.
- إحصائيات الطلبات والمتبرعين ووقت الاستجابة ثابتة للعرض. عدادات المراجعات والبلاغات والشراكات تُحسب من البيانات المحلية.
- قبول ورقة غير شريك لا يمنح علامة «موثّق»؛ الواجهة توضّح الفرق بينها وبين «ورقة تبدو سليمة».

## ظهور العنوان وحده بعد النشر

بادئة كلاسات الإدارة هي `bl-admin-`. تجنّب اختصارها إلى `ad-`؛ أسماء مثل `ad-content` و`ad-header` و`ad-sidebar` مدرجة في قوائم حجب الإعلانات، وقد تُخفي المحتوى رغم نجاح البناء والدمج ووجود البيانات. عند التحقق من النشر، جرّب بناء الإنتاج (`npm run build` ثم `npm run preview`) بجانب تجربة خادم التطوير. هذا التعارض لا يحتاج إلى Backend أو تغيير إعدادات Vercel.

## تنظيم الكود

كل كود الجزء موجود في `client/src/pages/admin/`:

- `AdminLayout.jsx` و`admin.css`: الهيكل والتصميم المتجاوب وأدوات العرض.
- `AdminProvider.jsx` و`AdminContext.js`: حالة العرض المشتركة وحفظ القرارات.
- `adminData.js`: البيانات التجريبية وتنسيق الأرقام والتواريخ والبحث العربي.
- `AdminUI.jsx`: الجداول والمرشحات والنوافذ ومعاينة المستند ونموذج اتخاذ القرار.
- ملفات `Admin*Page.jsx` الأربعة: محتوى الصفحات.

التعديل خارج مجلد الإدارة مقتصر على `App.jsx` لربط المسارات بالهيكل الإداري. لم تتغير صفحات باقي الأدوار أو تبعيات المشروع. عند إضافة Backend لاحقًا، استبدل التعامل مع البيانات داخل الـProvider باستدعاءات API، وأضف المصادقة والتحقق من الصلاحيات على السيرفر.

التحقق: بناء الإنتاج ناجح، وفحص ESLint لملفات الإدارة و`App.jsx` ناجح. جرى اختبار البحث، حفظ قرار الورقة بعد إعادة التحميل، الحظر وإلغائه، اعتماد مستشفى، الفلاتر والترقيم في المتصفح، وفحص العرض على الكمبيوتر وعرض هاتف 390 بكسل.
